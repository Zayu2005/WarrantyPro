# 07 接口设计概要

> 前置阅读：[06-数据库设计](./06-数据库设计.md)
> 本文约定 API 规范与核心接口清单。角色标识与 [02 需求分析 §1](./02-需求分析.md) 一致：OWNER 业主 / WORKER 师傅 / DISPATCHER 客服 / MANAGER 管理层 / ADMIN 管理员。

---

## 1. 设计规范

- **风格**：RESTful，基础路径 `/api/v1`，JSON 交互；
- **鉴权**：除 `auth/*` 外全部需要 `Authorization: Bearer <JWT>`；接口级 RBAC（下表"角色"列）；
- **统一响应体**：

```json
{ "code": 0, "message": "ok", "data": { } }
```

- **分页**：请求 `?page=1&pageSize=20`，响应 `data: { "list": [], "total": 0, "page": 1, "pageSize": 20 }`；
- **时间**：ISO-8601 字符串（`2026-09-09T14:30:00+08:00`）；
- **幂等**：写操作支持 `Idempotency-Key` 请求头（派单、提交工单等关键操作）。

## 2. 接口清单

### 2.1 认证与账号（/auth、/bindings）

| 方法 | 路径 | 角色 | 说明 |
|------|------|------|------|
| POST | /auth/sms-code | 公开 | 发送验证码（60s 限流） |
| POST | /auth/register | 公开 | 业主注册（绑定房屋需管理员审核） |
| POST | /auth/login | 公开 | 用户名 + 密码登录，返回 AccessToken + RefreshToken |
| POST | /auth/refresh | 公开 | 刷新令牌 |
| POST | /auth/logout | 全部 | 登出（token 入 Redis 黑名单） |
| GET | /auth/me | 全部 | 当前用户信息与角色 |
| POST | /bindings | OWNER | 申请绑定房屋 |
| GET | /houses/my | OWNER | 我的房屋列表 |

### 2.2 工单·业主视角（/orders）

| 方法 | 路径 | 角色 | 说明 |
|------|------|------|------|
| POST | /orders | OWNER | 提交工单（表单或 AI 草稿确认，见 §3.1） |
| GET | /orders/my | OWNER | 我的工单（状态 / 时间筛选，分页） |
| GET | /orders/{id} | OWNER/WORKER/DISPATCHER | 工单详情 + 时间轴（order_flow_record） |
| POST | /orders/{id}/cancel | OWNER | 撤销（仅 SUBMITTED 状态） |
| POST | /orders/{id}/confirm | OWNER | 验收：`{ "pass": true/false, "reason": "…" }` |
| POST | /orders/{id}/evaluation | OWNER | 评价：`{ "stars": 5, "tags": ["速度快"], "comment": "…" }` |

### 2.3 工单·客服调度视角（/dispatch）

| 方法 | 路径 | 角色 | 说明 |
|------|------|------|------|
| GET | /dispatch/orders | DISPATCHER | 工单池（状态 / 故障类别 / 小区 / 紧急度筛选） |
| POST | /dispatch/orders/{id}/accept | DISPATCHER | 受理并触发自动派单；无候选时工单保持 PENDING_DISPATCH |
| POST | /dispatch/orders/{id}/dispatch | DISPATCHER | 待派单工单人工指定当日值班师傅 `{ "workerId": 12, "reason": "…" }` |
| POST | /dispatch/orders/{id}/urge | DISPATCHER | 催办 |
| POST | /dispatch/orders/{id}/close | DISPATCHER | 关单（无效工单 / 外部处理完成确认） |
| GET | /dispatch/reassign-requests | DISPATCHER | 师傅改派申请列表 |
| POST | /dispatch/reassign-requests/{id}/approve | DISPATCHER | 同意改派（工单回流派单池） |

### 2.4 工单·师傅视角（/worker）

| 方法 | 路径 | 角色 | 说明 |
|------|------|------|------|
| GET | /worker/orders | WORKER | 待办：DISPATCHED（已派待上门）+ IN_PROGRESS（进行中） |
| POST | /worker/orders/{id}/arrive | WORKER | 到场打卡（DISPATCHED → IN_PROGRESS） |
| GET | /worker/orders/{id}/assist | WORKER | AI 维修方案推荐（相似工单 + 知识库 + 建议摘要） |
| POST | /worker/orders/{id}/report-draft | WORKER | AI 生成维修记录草稿（师傅确认后随 complete 提交） |
| POST | /worker/orders/{id}/complete | WORKER | 完工提交 `{ "faultCause", "measures", "materials", "workHours", "afterPhotoIds" }` |
| GET | /worker/performance | WORKER | 个人绩效（接单量 / 时效 / 评分） |

### 2.5 Agent（/agent）

| 方法 | 路径 | 角色 | 说明 |
|------|------|------|------|
| POST | /agent/chat | OWNER / WORKER | **SSE 流式对话**（小保报修助手 / 维修辅助），事件协议见 §4.2 |
| GET | /agent/sessions | OWNER / WORKER | 我的会话列表（恢复上下文） |
| POST | /agent/nl-query | MANAGER | 自然语言查数（受限指标域，返回数据 + 结论摘要） |
| POST | /agent/weekly-report | MANAGER | 生成周报 / 月报 `{ "startDate", "endDate" }` |

#### 2.5.1 LangChain4j 报修分诊工作流

| 方法 | 路径 | 角色 | 说明 |
|------|------|------|------|
| GET | /agent/workflows/definition | ADMIN / MANAGER / DISPATCHER | 获取流程节点与边，用于管理后台绘制流程图 |
| POST | /agent/workflows/repair-triage/runs | ADMIN / MANAGER / DISPATCHER / OWNER / WORKER | 创建一次异步报修分诊运行，立即返回 `RUNNING` 记录 |
| GET | /agent/workflows/runs?limit=30 | ADMIN / MANAGER / DISPATCHER | 查询最近工作流运行记录 |
| GET | /agent/workflows/runs/{id} | ADMIN / MANAGER / DISPATCHER | 查询单次运行状态与最终结果 |
| GET | /agent/workflows/runs/{id}/logs | ADMIN / MANAGER / DISPATCHER | 查询节点调用日志；管理后台每 2 秒轮询刷新 |

工作流固定经过“报修理解 → 故障分类 → 知识检索 → 维修方案草拟 → 安全与格式校验 → 输出分诊结果”六个节点。分类和方案节点通过 LangChain4j 调用 OpenAI 兼容模型；未配置 `WARRANTY_AI_API_KEY` 或模型调用失败时记录 `DEGRADED`，使用规则结果继续完成流程。

> 派单规则由工单受理事件触发；无候选时客服通过人工派单接口兜底。决策日志供审计接口查询（ADMIN，`GET /agent/decision-logs`）。

## 3. 关键接口示例

### 3.1 提交工单 `POST /api/v1/orders`

```json
{
  "source": "AI_CHAT",
  "houseId": 3021,
  "objectType": "INDOOR",
  "category": "土建防水",
  "locationDetail": "主卫顶部",
  "phenomenon": "顶面渗水滴落，近两天持续，疑似楼上防水失效",
  "urgency": "NORMAL",
  "photoIds": [881, 882],
  "draftSessionId": 57
}
```

响应 `data`：

```json
{
  "orderId": 1024,
  "orderNo": "WO202609090001",
  "status": "SUBMITTED",
  "verdict": {
    "result": "IN_WARRANTY",
    "responsibleParty": "DEVELOPER",
    "basis": "法定·屋面及有防水要求部位 5 年（条例第四十条）",
    "warrantyExpire": "2028-06-30"
  }
}
```

### 3.2 派单决策留痕（当前版本不提供独立推荐接口）

客服受理后后端按负载、位置和评分计算候选并自动直派；无候选时留在待派单状态，由客服人工指定当日值班师傅。派单候选与决策原因保存在决策日志中；以下响应结构仅为后续推荐接口设计示例，不是当前可调用接口：

```json
{
  "candidates": [
    { "workerId": 12, "name": "张师傅", "skillTags": ["水电", "土建防水"],
      "score": 0.86, "factors": { "load": 0.67, "location": 1.0, "rating": 0.96 },
      "inProgressOrders": 1 },
    { "workerId": 8, "name": "李师傅", "skillTags": ["水电"],
      "score": 0.79, "factors": { "load": 1.0, "location": 1.0, "rating": 0.88 },
      "inProgressOrders": 0 }
  ],
  "recommendation": 12,
  "reason": "当前仅 1 单在处理，常驻本小区，历史评分 4.8/5，综合得分最高。",
  "mode": "RECOMMEND"
}
```

### 3.3 SSE 对话 `POST /api/v1/agent/chat`

请求：`{ "sessionId": 57, "agentType": "XIAOBAO", "message": "卫生间顶上漏水" }`
响应为 `text/event-stream`，事件类型：`message` / `kb_advice` / `draft` / `done` / `degraded`（定义见 [05 §3.5](./05-AI-Agent功能设计.md)）。

## 4. 实时通道约定

### 4.1 WebSocket `/ws`（工单进度推送）

- 鉴权：连接参数携带 token；
- 订阅：客户端发送 `{ "action": "SUBSCRIBE", "topics": ["order:1024", "dashboard"] }`；
- 服务端推送：

```json
{ "topic": "order:1024", "event": "ORDER_STATUS_CHANGED",
  "data": { "from": "DISPATCHED", "to": "IN_PROGRESS", "operator": "张师傅", "at": "2026-09-09T14:30:00+08:00" } }
```

### 4.2 SSE 与 WebSocket 的分工

| 通道 | 用途 | 消费端 |
|------|------|--------|
| SSE `/agent/chat` | Agent 流式对话（单向 token 流） | 鸿蒙端、PC 端 |
| WebSocket `/ws` | 工单状态变更、催办提醒、大屏指标刷新 | 三端 |

## 5. 错误码

| code | 含义 | 典型场景 |
|------|------|---------|
| 0 | 成功 | |
| 40101 | 未登录 / token 失效 | |
| 40301 | 无权限 | 业主访问他人工单 |
| 40401 | 资源不存在 | |
| 40901 | 状态冲突 | 对已完结工单执行验收、重复派单 |
| 42201 | 参数校验失败 | 槽位缺失、照片超限 |
| 42901 | 请求过频 | 验证码、AI 对话限流 |
| 50001 | 系统异常 | |
| 50301 | AI 服务不可用（已降级） | 对话接口返回，前端切换表单 |
| 50302 | 模型输出校验失败 | Schema 校验未过且重试超限 |
