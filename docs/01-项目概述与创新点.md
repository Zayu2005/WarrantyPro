# 01 项目概述与创新点

> 项目名称：数字化物业保修平台（WarrantyPro）
> 文档定位：项目背景、建设目标、核心创新点 —— 建议评审首先阅读本文档。

---

## 1. 项目背景

### 1.1 行业现状与痛点

物业维修是社区治理中频次最高、矛盾最集中的场景之一。调研当前主流住宅小区的维修管理方式，普遍存在以下痛点：

| # | 痛点 | 具体表现 |
|---|------|---------|
| P1 | **报修渠道原始** | 电话报修、微信留言、物业前台口头登记，故障信息缺失、口头转述失真，"报修靠吼、描述靠猜" |
| P2 | **流转全靠人工** | 纸质单据、微信群喊人派活，工单状态无迹可查，业主只能反复打电话催问进度 |
| P3 | **保修责任界定不清** | 房屋不同部位保修期各不相同（屋面防水 5 年、水电安装 2 年等），物业、开发商、业主三方责任推诿多发，"该谁修"成为扯皮焦点 |
| P4 | **派单凭经验** | 客服按个人印象派单，技能不匹配导致返工，师傅忙闲不均，服务质量无数据支撑 |
| P5 | **数据无沉淀** | 维修记录散落在纸质单据和聊天记录中，无法支撑设施设备全生命周期管理、师傅绩效评估和管理层决策 |

### 1.2 政策与技术趋势

- **政策驱动**：《建设工程质量管理条例》明确了各分部工程的最低保修期限与责任主体；《"十四五"城乡社区服务体系建设规划》等文件持续推动智慧社区、物业管理数字化转型。
- **技术机遇**：
  - 鸿蒙生态（HarmonyOS NEXT）快速崛起，「一次开发、多端部署」为社区场景的多端覆盖提供了原生底座；
  - 大语言模型与 RAG、Function Calling 技术走向成熟，使 AI Agent 能够真正"动手操作"业务系统，而不只是聊天。

**结论**：将「报修工单流转」与「保修台账管理」两条业务线数字化、智能化，并用 AI Agent 重构关键环节，是一个技术上可行、业务上刚需、政策上契合的选题。

## 2. 项目定位与建设目标

### 2.1 一句话定位

> **WarrantyPro** 是一个面向住宅小区的「报修 + 保修」一体化数字平台：业主在鸿蒙端通过与 AI 助手对话完成报修，系统自动判定保修责任、智能派单给维修师傅，全流程透明可追溯；物业在 PC 端完成工单调度、保修台账管理与数据化运营。

### 2.2 建设目标

| # | 目标 | 衡量指标 |
|---|------|---------|
| G1 | 报修零门槛 | 业主 1 分钟内完成一次合格报修（对话式），故障描述结构化完整率 ≥ 90% |
| G2 | 责任界定自动化 | 报修工单 100% 经过保修判定引擎，自动给出责任方与条款依据 |
| G3 | 派单智能化 | 技能匹配准确率 ≥ 90%，平均派单时长从"小时级"降至"分钟级" |
| G4 | 进度全透明 | 业主随时可查工单状态时间轴，催问电话下降 ≥ 60% |
| G5 | 数据资产化 | 保修台账、维修记录、师傅绩效全量沉淀，支撑管理层决策 |

## 3. 用户与产品形态总览

系统采用「**三端一云 + AI Agent**」形态：

| 端 | 载体 | 目标用户 | 核心能力 |
|----|------|---------|---------|
| 鸿蒙端·业主 | HarmonyOS App（ArkTS） | 业主 / 住户 | 对话式智能报修、表单报修（降级）、进度追踪、验收评价、服务卡片 |
| 鸿蒙端·师傅 | 同一 App 按角色切换 | 维修师傅 | 接单 / 改派、维修执行、AI 维修方案推荐、维修记录 AI 辅助生成 |
| PC 管理后台 | Web（Vue3 + Element Plus） | 物业客服、管理层、系统管理员 | 工单受理与派单确认、保修台账、统计大屏、自然语言查数、系统管理 |
| 云端服务 | Spring Boot 3 后端 | — | 统一 API、保修判定引擎、智能派单 Agent、RAG 知识库、推送与通知 |

> 详细的角色职责与用例见 [02-需求分析](./02-需求分析.md)。

## 4. 核心创新点（评审重点）

### 创新点 1：对话式 AI 报修助手「小保」—— 把"填表"变成"聊天"

- **做法**：业主在鸿蒙端与 AI 助手多轮对话（追问故障位置、现象、持续时间），上传照片自动识别故障类型（漏水 / 电路 / 门窗损坏等），最终自动生成**结构化工单预填单**，业主确认后一键提交。
- **前置拦截**：报修前基于 RAG 知识库给出自助排障建议（如跳闸复位、马桶轻微堵塞），可自行解决则不必建单，减少无效工单。
- **解决痛点**：P1（报修渠道原始、信息缺失）。
- **可行性**：基于 Spring AI + 多模态大模型 API + 槽位填充提示词工程实现，技术成熟；对话全程 SSE 流式输出，体验流畅。

### 创新点 2：可解释的智能派单 Agent —— 派单从"拍脑袋"到"给理由"

- **做法**：系统按「技能匹配 × 负载空闲 × 位置就近 × 历史评分」多因子加权评分产出候选师傅，再由 Agent 进行在岗校验、规则过滤并生成**自然语言推荐理由**（如"张师傅：水电类 3 年经验、当前仅 1 单在处理、距该楼栋 400 米、近 90 天评分 4.8"）；客服一键确认，或配置为全自动派单 + 超时自动改派。
- **解决痛点**：P4（派单凭经验、忙闲不均）。
- **可行性**：评分函数确定性可测，LLM 仅负责规则校验与理由生成，决策日志全量落库可审计；大模型不可用时降级为纯规则评分派单。

### 创新点 3：保修期智能判定与责任路由引擎 —— 让"该谁修"有法可依

- **做法**：历史版本曾根据《建设工程质量管理条例》和物业合同判定保修责任。当前新工单不再按保修结果分流，统一由物业受理并派单；旧判定字段仅为历史数据与客户端兼容保留。
- **解决痛点**：P3（责任界定不清、三方推诿）。
- **可行性**：规则引擎 + 日期比较实现，零 AI 依赖、100% 确定性，是系统的"可靠性压舱石"。

### 创新点 4：报修进度全透明 + 鸿蒙服务卡片

- **做法**：工单每次状态流转实时推送；业主可将工单进度添加为**鸿蒙服务卡片（Service Widget）**，在桌面一瞥即知维修进展；维修前后照片留痕，验收有据。
- **解决痛点**：P2（流转靠人工、进度黑箱）。

### 创新点 5：保修资产台账可视化与到期预警

- **做法**：小区公共设施设备（电梯、消防、水泵、外立面等）建立保修台账，大屏可视化呈现保修健康度；保修临期自动预警，提示物业提前组织查验、与开发商交涉续保。
- **解决痛点**：P5（数据无沉淀）+ 变"事后维修"为"事前管理"。

### 创新点 6：鸿蒙原生「一次开发、多端部署」与端云协同

- **做法**：业主端与师傅端共用一套 ArkTS 代码库按角色渲染；使用 Push Kit 实现派单、进度消息的实时触达；自适应布局覆盖手机 / 平板。
- **价值**：贴合国产化生态趋势，是与其他参赛作品形成差异化的技术名片。

### 可靠性设计亮点：AI 全链路可降级

每个 AI 能力均有非 AI 降级路径：对话报修 → 传统表单报修；Agent 派单 → 规则加权派单；Agent 周报 → 模板报表。**核心业务链路（报修-派单-维修-验收）在完全无大模型的条件下依然可用**，兼顾创新性与工程可靠性。

## 5. 与传统模式对比

| 维度 | 传统物业维修模式 | WarrantyPro |
|------|----------------|-------------|
| 报修方式 | 电话 / 口头 / 纸质单 | 对话式 AI 报修 + 照片识别，一键提交 |
| 信息质量 | 描述缺失、转述失真 | 结构化工单（位置 / 部位 / 现象 / 照片 / 紧急度） |
| 保修责任 | 人工翻合同，扯皮多 | 判定引擎自动给出责任方 + 条款依据 |
| 派单 | 凭印象派单 | 多因子评分 + Agent 推荐理由，可自动派单 / 改派 |
| 进度查询 | 反复电话催问 | 时间轴 + 推送 + 鸿蒙服务卡片 |
| 维修知识传承 | 师傅个人经验 | 相似工单检索 + 知识库，AI 辅助生成维修记录 |
| 数据沉淀 | 散落丢失 | 保修台账、绩效、统计大屏全量沉淀 |

---

## 6. 预期效益

- **对业主**：报修更简单、进度更透明、结果可评价；
- **对物业**：客服效率提升（无效工单前置拦截、派单自动化）、责任界定有据、管理决策有数；
- **对维修师傅**：工单分配公平透明、AI 辅助提升一次修复率、绩效凭数据说话；
- **对开发商 / 社区治理**：保修责任清晰化，减少三方纠纷，契合智慧社区政策导向。
