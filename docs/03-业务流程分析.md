## 1. 工单状态机（全文档统一口径）

```mermaid
stateDiagram-v2
    SUBMITTED: 待受理
    PENDING_DISPATCH: 待派单
    EXTERNAL_PROCESSING: 外部处理中（保修期内）
    DISPATCHED: 待接单（已派单）
    IN_PROGRESS: 维修中
    PENDING_CONFIRM: 待验收
    COMPLETED: 已完结
    CANCELLED: 已取消

    [*] --> SUBMITTED: 业主提交报修
    SUBMITTED --> PENDING_DISPATCH: 客服受理（保修期外）
    SUBMITTED --> EXTERNAL_PROCESSING: 客服受理（保修期内）
    SUBMITTED --> CANCELLED: 业主撤销 / 无效关单
    PENDING_DISPATCH --> DISPATCHED: 派单确认（Agent 推荐 / 人工）
    PENDING_DISPATCH --> CANCELLED: 客服关单
    DISPATCHED --> IN_PROGRESS: 师傅接单
    DISPATCHED --> PENDING_DISPATCH: 师傅拒单 / 接单超时自动改派
    IN_PROGRESS --> PENDING_CONFIRM: 师傅完工提交
    IN_PROGRESS --> PENDING_DISPATCH: 师傅申请改派（客服同意）
    PENDING_CONFIRM --> COMPLETED: 验收通过 / 验收超时默认通过
    PENDING_CONFIRM --> IN_PROGRESS: 验收不通过（返工）
    EXTERNAL_PROCESSING --> COMPLETED: 外部处理完成，客服确认关单
    COMPLETED --> [*]
    CANCELLED --> [*]
```

**状态说明**

| 状态 | 含义 | 责任人 |
|------|------|--------|
| SUBMITTED 待受理 | 工单已提交，等待客服受理 | 物业客服 |
| PENDING_DISPATCH 待派单 | 已受理（保修期外），等待派单 | 系统 / 物业客服 |
| EXTERNAL_PROCESSING 外部处理中 | 保修期内，已通知开发商 / 承建商对接人 | 物业客服跟进 |
| DISPATCHED 待接单 | 已派给师傅，等待接单 | 维修师傅 |
| IN_PROGRESS 维修中 | 师傅已接单（已到场 / 处理中） | 维修师傅 |
| PENDING_CONFIRM 待验收 | 完工已提交，等待业主验收 | 业主 |
| COMPLETED 已完结 | 验收通过（或外部处理完成） | — |
| CANCELLED 已取消 | 业主撤销、无效工单或客服关单 | — |

## 2. 总体业务流程

```mermaid
flowchart TD
    A["业主发现故障"] --> B{"选择报修方式"}
    B -- AI 可用 --> C["对话式报修（小保）"]
    B -- AI 降级 --> D["表单报修"]
    C --> E{知识库命中<br/>可自助解决?}
    E -- 是 --> F["给出自助排障建议"]
    F --> G{业主确认已解决?}
    G -- 是 --> Z0["无需建单，会话记录留存"]
    G -- 否 --> H["生成工单预填单"]
    D --> H2["工单信息（部位/现象/照片/紧急度）"]
    H --> I["业主确认提交"]
    H2 --> I
    I --> J["保修判定引擎<br/>（自动判定责任方）"]
    J --> K{"判定结果"}
    K -- "保修期内" --> L["通知开发商/承建商对接人<br/>EXTERNAL_PROCESSING"]
    K -- "保修期外" --> M["智能派单 Agent<br/>（推荐/自动派单）"]
    K -- "人为损坏" --> N["业主有偿维修<br/>（走物业派单，标记收费）"]
    M --> O["师傅接单 → 到场 → 维修<br/>（AI 方案推荐辅助）"]
    N --> O
    L --> P["外部处理完成，客服确认"]
    O --> Q["完工提交（照片+维修记录）"]
    Q --> R{"业主验收"}
    R -- 通过 --> S["评价（星级+标签）"]
    R -- 不通过 --> O2["返工（回到维修中）"]
    O2 --> Q
    P --> T["工单完结"]
    S --> T
    T --> U["数据沉淀：保修台账 / 师傅绩效 / 知识库 / 统计大屏"]
```

## 3. 前端报修流程：对话式（主）与表单（降级）

### 3.1 对话式报修时序

```mermaid
sequenceDiagram
    autonumber
    participant O as 业主（鸿蒙端）
    participant A as 小保 Agent（后端）
    participant L as 大模型 API
    participant K as RAG 知识库
    participant S as 工单服务

    O->>A: 发起对话：'卫生间顶上漏水'
    A->>L: 组装上下文 + 槽位引导提示词（SSE 流式）
    L-->>A: 追问：具体位置/持续时间/是否持续
    A-->>O: 流式回复（追问）
    O->>A: 补充描述 + 上传照片
    A->>L: 多模态识别照片故障类型
    L-->>A: 卫生间顶部渗漏（疑似楼上防水失效）
    A->>K: 检索相似故障的自助排障建议
    K-->>A: 命中：先联系楼上住户观察用水时段…
    A-->>O: 建议先自查；若需维修可一键生成工单
    O->>A: 确认生成工单
    A->>S: createOrderDraft（房屋/部位/故障类型/紧急度/照片）
    S-->>A: 工单草稿（含保修预判定）
    A-->>O: 展示结构化预填单，业主确认
    O->>S: 提交工单（SUBMITTED）
    S-->>O: 提交成功，进入受理流程
```

### 3.2 表单报修（降级方式）

固定表单字段：报修房屋（默认绑定房屋，可切换）→ 报修对象（户内部位 / 公共设施）→ 部位类别（水电 / 土建防水 / 门窗 / 暖通 / 电梯 / 其他）→ 故障描述 → 照片（≤6 张）→ 紧急程度（紧急 / 普通）。提交后进入同一受理与判定流程，与对话式工单无差别。

## 4. 保修判定引擎流程

判定依据：《建设工程质量管理条例》第四十条法定最低保修期限 + 物业合同自定义条款（合同优先）。

| 工程部位 | 法定最低保修期限 |
|---------|----------------|
| 地基基础与主体结构 | 设计文件规定的合理使用年限 |
| 屋面防水、有防水要求的卫生间 / 房间 / 外墙面防渗漏 | 5 年 |
| 供热与供冷系统 | 2 个采暖期 / 供冷期 |
| 电气管线、给排水管道、设备安装与装修工程 | 2 年 |
| 保温工程 | 5 年 |

```mermaid
flowchart TD
    A["工单提交"] --> B{"故障性质初判"}
    B -- "人为损坏 / 不当使用" --> C["责任方：业主<br/>有偿维修（标记收费）"]
    B -- "自然损坏" --> D["定位保修主体"]
    D -- "户内部位" --> E["起算日 = 楼栋竣工日期"]
    D -- "公共设施" --> F["起算日 = 设施台账保修起始日<br/>（如电梯出厂验收日）"]
    E --> G["匹配保修规则<br/>（合同规则优先，缺省取法定）"]
    F --> G
    G --> H["保修到期日 = 起算日 + 保修期限"]
    H --> I{"当前日期 ≤ 到期日?"}
    I -- "是（保修期内）" --> J["责任方：开发商 / 承建商<br/>路由 EXTERNAL_PROCESSING<br/>自动通知对接人"]
    I -- "否（保修期外）" --> K["责任方：物业<br/>路由 PENDING_DISPATCH<br/>（户内可标记有偿）"]
    J & K & C --> L["输出判定书：结果 + 责任方 + 依据条款 + 起算日"]
    L --> M["客服受理时可复核纠正（留痕）"]
```

**判定结果数据结构**（后端统一返回，业主端仅展示通俗结论）：

```json
{
  "verdict": "IN_WARRANTY",          // IN_WARRANTY / OUT_OF_WARRANTY / OWNER_RESPONSIBLE
  "responsibleParty": "DEVELOPER",   // DEVELOPER / PROPERTY / OWNER
  "basisRule": "法定·屋面防水工程 5 年（条例第四十条）",
  "warrantyStart": "2023-06-30",
  "warrantyExpire": "2028-06-30",
  "routeTo": "EXTERNAL_PROCESSING"
}
```

## 5. 智能派单与自动改派流程

### 5.1 派单算法（详见 [05-AI-Agent功能设计](./05-AI-Agent功能设计.md) §4）

**Step 1 候选过滤**（确定性规则）：在岗（`on_duty`）且当日有排班 且 进行中工单数 < 上限（默认 3）；**技能不限领域**，仅作评分偏好（精确 1.0 / 相关 0.6 / 其他 0.3）。

**Step 2 多因子加权评分**：

```
Score = 0.4 × 技能匹配度 + 0.25 × 负载空闲度 + 0.2 × 位置就近度 + 0.15 × 历史评分
```

| 因子 | 计算方式 | 权重 |
|------|---------|------|
| 技能匹配度 | 精确匹配故障类别 = 1.0；相关类别 = 0.6（如水电↔暖通）；其余 = 0 | 0.40 |
| 负载空闲度 | 1 − 进行中工单数 / 单量上限 | 0.25 |
| 位置就近度 | 师傅常驻小区与工单小区一致 = 1.0，否则按同小区 / 邻近配置衰减 | 0.20 |
| 历史评分 | 近 90 天平均评分 / 5.0（无评分新师傅取默认 0.8） | 0.15 |

**Step 3 Agent 决策**：对 Top3 候选做在岗 / 请假等规则复核，生成自然语言推荐理由；`agent_decision_log` 落库。

### 5.2 派单与改派流程（迭代 2 口径：无接单环节，智能体直派）

```mermaid
flowchart TD
    A["工单进入 PENDING_DISPATCH<br/>（客服受理事件触发）"] --> B["智能派单引擎"]
    B --> C["候选过滤：在岗 ∧ 当日排班 ∧ 负载未满<br/>（技能不限领域，仅作偏好）"]
    C --> D["四因子加权评分 → Top1"]
    D --> E["直派 DISPATCHED（待上门）<br/>dispatch_record + decision_log 落库"]
    E --> F["师傅端展示待上门"]
    F --> G{"到场截止前打卡?"}
    G -- "是，到场打卡" --> H["IN_PROGRESS 维修中 → 完工提交"]
    G -- "否，到场超时" --> I["定时任务自动改派<br/>排除原师傅，轮次 +1"]
    I --> J{"已达轮次上限 3?"}
    J -- "否" --> C
    J -- "是" --> K["决策日志 DEGRADED<br/>客服人工介入"]
    F -. "客服可随时人工改派<br/>（指定师傅或重新智能重派）" .-> C
```

## 6. 维修执行 → 验收 → 评价闭环

```mermaid
sequenceDiagram
    autonumber
    participant O as 业主（鸿蒙端）
    participant W as 师傅（鸿蒙端）
    participant S as 后端系统
    participant C as 物业客服（PC 端）

    S->>W: 智能直派通知（工单详情，无需接单）
    W->>S: 请求 AI 维修方案推荐（相似工单 + 知识库）
    S-->>W: 方案建议 + 材料清单 + 历史案例
    W->>S: 到场打卡 / 处理中打卡
    S-->>O: 服务卡片与时间轴实时刷新
    W->>S: 完工提交（维修记录 + 前后照片）
    Note over W,S: 维修记录可由 AI 依据对话与照片生成草稿
    S-->>O: 推送：维修完成，请验收
    O->>S: 验收（通过 / 不通过）
    alt 验收通过
        S->>O: 邀请评价（星级 + 标签 + 评论）
        O->>S: 提交评价
        S->>W: 评价同步（计入绩效）
        S->>S: 工单 COMPLETED，数据沉淀
    else 验收不通过
        O->>S: 填写返工原因
        S-->>W: 推送返工通知（PENDING_CONFIRM → IN_PROGRESS）
        W->>S: 再次处理 → 重新提交完工
    else 48 小时未验收
        S->>S: 默认验收通过（可配置），COMPLETED
    end
    C-->>S: 全程可查看工单时间轴，超时环节催办
```

## 7. 保修到期预警流程（定时任务）

```mermaid
flowchart LR
    A["每日 02:00 定时任务"] --> B["扫描设施台账<br/>保修到期日 - 今天 ≤ 预警天数（默认 90）"]
    B --> C["生成/更新预警记录"]
    C --> D["通知管理层（站内信 + 大屏红点）"]
    D --> E["管理层安排临期查验<br/>与开发商交涉续保"]
    E --> F["处理结果登记，闭环预警"]
```

## 8. 超时催办阈值（默认值，管理员可配置）

| 环节 | 阈值 | 超时动作 |
|------|------|---------|
| 客服受理（普通 / 紧急） | 30 分钟 / 10 分钟 | 提醒客服，大屏标黄 |
| 师傅接单 | 15 分钟 | 自动改派（次优候选顺延） |
| 上门到场（普通 / 紧急） | 接单后 4 小时 / 2 小时 | 催办推送师傅 |
| 完工提交 | 接单后 24 小时 | 催办推送师傅，通知客服 |
| 业主验收 | 48 小时 | 默认验收通过 |
| 外部处理跟进 | 每工单 7 天未更新进展 | 提醒客服跟进开发商 |
